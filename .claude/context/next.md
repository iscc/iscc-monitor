## Step: Adopt iscc-lib Go codec + bump the locked toolchain to Go 1.26 (ADR-0011)

## Advances
This closes the open `normal` issue **"Adopt the iscc-lib Go codec + bump the toolchain to Go 1.26
(ADR-0011)"** (Source [human]), which `state.md`, `handoff.md`, and `CLAUDE.md` all explicitly

`target.md` **"Stack (locked — ADR-0003, ADR-0011)"** gap that `state.md` files as the "TARGET/CODE

M-UI tail (OTS §5, WASM verifier) per the handoff's `**Next:**` ("The ADR-0011 iscc-lib/Go-1.26
toolchain bump remains a queued `normal` foundational change to sequence before more feature work").

## Goal
Bump the toolchain Go 1.24 → 1.26 across the four config surfaces, add the pinned
`github.com/iscc/iscc-lib/packages/go` v0.5.0 dependency, and make it real with ONE tripwire/parity
test in `internal/index` that asserts iscc-lib **currently rejects** the known ISCC-IDv1
`"MAIGHFECJMOPMIAB"` with a Version error — so when iscc-lib#43 lands the assertion flips red and
signals "migrate the in-repo port". The production codec leaf (`iscc.go`) stays pure stdlib and
WASM-buildable.

## Implementation Notes
- **The toolchain bump and the dep add are atomic — land them together.** Verified locally: under Go
  1.24, `go mod download github.com/iscc/iscc-lib/packages/go@v0.5.0` prints
  *"requires go >= 1.26.1; switching to go1.26.4"* (iscc-lib's `go.mod` declares `go 1.26.1`,
  ADR-0011's patch-pin caveat). Adding the require with `go.mod` still at `1.24.0` is incoherent, so
  bump `mise.toml` + `go.mod`'s `go` directive in the same step. `mise install` provisions 1.26
  (verified: `mise ls-remote go` lists `1.26.0`–`1.26.4`); `mise.toml` is the single source of truth,
  the Dockerfile only comments it. Run `mise install` before the gate so `go version` is `go1.26.x`.
- **`go` directive vs `toolchain` line.** Prefer `go 1.26.1` (matching iscc-lib's floor); the current
  `go.mod` has NO `toolchain` line — keep it that way if `mise run check` is green without one. Add an
  explicit `toolchain go1.26.x` only if the gate complains. Run `go mod tidy` to populate `go.sum`:
  three NEW transitive deps land (`github.com/zeebo/blake3`, `golang.org/x/text`,
  `github.com/klauspost/cpuid/v2` // indirect) — all pure-Go / `CGO_ENABLED=0`-clean per ADR-0011.
- **The tripwire test is the load-bearing engineering.** It imports iscc-lib and asserts
  `IsccDecode("MAIGHFECJMOPMIAB")` returns a NON-nil error whose message contains `"invalid Version"`
  (the Version-1 rejection). Use a clear test name like `TestISCCLibRejectsISCCIDv1Today`. Add a
  comment citing `iscc/iscc-lib#43` and: "when this assertion flips RED, iscc-lib decodes ISCC-IDv1 →
  migrate `internal/index.Decode` to iscc-lib and delete the port (ADR-0011 migration trigger)."
  `"MAIGHFECJMOPMIAB"` is the SAME golden vector `iscc_test.go:35` uses, so the tripwire and the port
  test agree on the subject — the tripwire proves iscc-lib rejects exactly what the in-repo port
  handles. Assert the bare form (safe); only add an `"ISCC:"`-prefixed sub-case if you first confirm
  iscc-lib's accepted input shape — do not guess.
- **Purity rule (learnings index + ADR-0011):** the TEST may import iscc-lib, but `iscc.go` must NOT.
  After the change confirm `GOOS=js GOARCH=wasm go build ./internal/index` STILL succeeds (it builds
  today — baseline confirmed). The WASM build excludes `_test.go` files, so the test's iscc-lib import
  never leaks into the WASM artifact — this is ADR-0011's explicit guard.
- **Correctness rule (learnings index):** `internal/index` is the "pure WASM-shareable ISCC-IDv1
  decoder; all 4 header nibbles fail-closed incl. Length=0; golden vector grounded in hub schema.py
  example." Do not regress any existing `internal/index` golden/mutation test.
- **Oracle/conformance gate: N/A** — this step adds a dependency + a tripwire test and does NOT touch
  signature verification, RFC-6962/Merkle consistency, or proof code. Do not weaken any gate.
