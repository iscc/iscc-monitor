# ISCC brand edition 01 alignment, shared site chrome, and operator co-branding

ADR-0010 adopted the Evidence Ledger direction on the ISCC Design System v2 token bundle
(`.claude/design/_ds/`). The ISCC brand guidelines have since been reissued as **edition 01**
(the `iscc-brand` repository, `GUIDELINES.md` and the 34-page book). The edition keeps the
fonts and the ISCC-UNIT colours but changes the colour roles and the surface treatment, and
the DS v2 bundle predates it. Two concrete conflicts existed: the dashboard's ISCC-ID input and
the certificate's subject banner set white text on coral (3.09:1, below WCAG AA for normal text,
and against the brand's "never set text on coral" button rule), and the masthead used an
all-black PNG instead of the brand's near-black/coral signature.

Separately, the monitor is built by the ISCC Foundation but may be run by other organizations.
A public site needs an operator identity and, in many jurisdictions, imprint and privacy links.
Each of the eight pages carried its own copy of the masthead markup and CSS, and there was no
footer, so neither could be added once.

**Decision.**

1. **Brand edition 01 wins over the DS v2 bundle for values.** `internal/web/tokens.css` keeps
   every DS v2 token *name* (so no page changes to pick the values up) but takes the edition's
   values: paper canvas `#F8F9FA`, near-black body text, muted `#636B71` (also for "faint"
   text, which carries dates and notes), rule grey `#D2D6D9`, coral as the brand accent, Readex
   Pro Regular for body copy (Light only at display sizes), Regular titles, square corners, and
   flat surfaces without shadows. The page layouts of ADR-0010 are unchanged. A future change
   must not "restore" the bundle values; the bundle remains the record of the original handoff.
2. **Brand assets are byte-verbatim masters.** The masthead logo is `iscc-logo-black-coral.svg`
   and the favicon is `iscc-icon-black-coral.svg`, copied unmodified (the brand forbids
   rebuilding or recolouring the logo).
3. **Brand buttons.** The primary action of a view is the brand's pointed near-black block with
   a white JetBrains Mono label and a coral chevron (`.btn-primary`); a second choice beside it
   is the 1.5px outline (`.btn-secondary`). Coral marks direction only. The certificate's
   subject banner keeps its coral field with near-black text (4.99:1).
4. **One shared chrome.** `internal/chrome` holds the masthead and footer partials, associated
   into every page template the way `internal/badge` is; `/_ds/site.css` styles them once. The
   footer shows the running version linked to its exact GitHub release or commit, the
   open-source credit, the instance links, and the operator line.
5. **Co-branding is identity, not theming.** Operators configure a name, website, logo, and
   footer links through environment variables, validated at startup. The ISCC mark, the
   palette, and the credit stay fixed, and the operator logo appears beside the ISCC mark with
   the factual label "Operated by", per the brand's co-branding rule. The logo file is read once
   and served from the instance at `/_ds/operator-logo` (with a restrictive CSP), so the no-CDN
   invariant holds. An accent-colour override was considered and rejected: it conflicts with
   the brand and adds a test surface for little value.

**Consequences.**

- The no-CDN tests now ban cross-origin *resource loads* (`src`, `srcset`, `<link href>`,
  CSS `url()`, `@import`) through `internal/web/webtest`, not every `https://` string: the
  footer links to the source repository, and a hyperlink loads nothing.
- The masthead identity type moved from `dashboard.Identity` to `chrome.Site`, removing four
  duplicated copies of the fallback copy and its resolver.
- `verify.wasm` and its pinned hash are unaffected: `cmd/wasm` imports no template package.
- The verifier site's footer shows its build version when the Pages workflow stamps one. *(Superseded:
  ADR-0016 removed the verifier site, its chrome mode and the masthead link to it.)*
- *(Added 2026-11-07.)* A certificate that proves inclusion carries the **ISCC Trust Seal** beside its title,
  with the issue time in a caption beneath. `internal/certificate/iscc-trust-seal.template.svg` is a
  byte-verbatim copy of the iscc-brand kit's `build/seal/iscc-trust-seal.template.svg` (generated by its
  `source/seal.py`); `seal.go` only substitutes the canonical ISCC-ID and the UTC date, which have fixed
  character positions. The kit's GUIDELINES.md "ISCC Trust Seal" section holds the usage rules: only on a
  proven inclusion, 96–128 px with the lettering, never near the ISO 24138 reference, not recoloured.
